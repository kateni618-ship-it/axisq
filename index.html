Web 应用如何运行？

用可视化图解，搞懂浏览器、服务器、数据库三者之间是怎么相互配合的，以及用户数据如何被安全地独立存储。

三大核心角色
任何 Web 应用，无论多复杂，都离不开这三个主角
🖥️

客户端（浏览器）

用户看到 & 操作的地方

你打开网页时，浏览器就是"客户端"。它负责把代码渲染成你能看懂的页面，并接收你的点击、输入等操作。

  • HTML — 网页骨架结构
  • CSS — 样式与视觉美化
  • JavaScript — 交互与动态逻辑
  • 将用户操作打包成"请求"发给服务器
⚙️

服务器（后端）

幕后大脑 & 决策中心

服务器是一台 24 小时运行的电脑（或云服务），接收浏览器发来的请求，经过逻辑处理后，决定要做什么，再把结果返回给浏览器。

  • 运行后端代码（Python / Node.js 等）
  • 处理业务逻辑（注册、登录、权限验证）
  • 与数据库交互，读写用户数据
  • 对外暴露 API 接口
🗄️

数据库

数据的永久存储仓库

数据库是专门存储数据的软件。无论用户关闭浏览器还是服务器重启，数据都不会丢失，就像一个超级整洁的电子档案室。

  • 结构化地存储用户、文章、订单等数据
  • 支持快速查询（"找出所有叫张三的用户"）
  • 常见类型：MySQL、PostgreSQL、MongoDB
  • 只有服务器才能直接访问数据库

    请求与响应长什么样？
    浏览器与服务器之间传递的是结构化的文本数据，以注册为例
    浏览器 → 服务器（HTTP 请求）
    POST /api/register HTTP/1.1
    Host: myapp.com
    Content-Type: application/json

    {
      "username": "张三",
      "email": "zhang@example.com",
      "password": "●●●●●●●●"
    }

    // 浏览器把用户填的表单
    // 打包成 JSON 发给服务器
    服务器 → 浏览器（HTTP 响应）
    HTTP/1.1 201 Created
    Content-Type: application/json

    {
      "success": true,
      "message": "注册成功！",
      "token": "eyJhbGci...XmQ",
      "user": {
        "id": 1042,
        "name": "张三"
      }
    }
    // token 是"登录凭证"，
    // 之后每次请求都带上它
    数据库里的数据长什么样？
    数据库把数据存在"表"里，就像 Excel 表格，每行是一条记录
    🗄️ users 表 — 存放所有注册用户
    id username email password_hash created_at
    1040 李四 li@example.com $2b$10$x9v… 2024-01-10 09:22
    1041 王五 wang@example.com $2b$10$kQ8… 2024-02-03 14:01
    1042 张三 ← 刚注册 zhang@example.com $2b$10$mJ7… 2024-03-02 11:45
    🔒 密码从不明文存储！ 注册时服务器会用 bcrypt 等算法把密码"哈希"成一串乱码再存入数据库。 就算数据库泄露，攻击者也无法还原出原始密码。每次登录验证时，服务器把你输入的密码再哈希一次，与数据库里的哈希值对比。
    用户数据如何做到"独立"存储？
    三个关键机制，确保每个用户只能看到自己的数据
    🪙

    Token 身份令牌

    登录成功后服务器颁发一个 Token（通常是 JWT），浏览器把它存在本地。之后每次请求都带上 Token，服务器解码后就知道"是谁在请求"，从而只返回该用户的数据。

    🆔

    用户 ID 隔离

    数据库每条记录都挂着 user_id 字段。服务器查询时加上 WHERE user_id = 当前用户 的条件，从根本上保证用户 A 的请求不会读出用户 B 的数据。

    🔐

    服务器是唯一入口

    浏览器（包括黑客的浏览器）根本无法直接连接数据库。数据库只对服务器开放内网端口，这层隔离是安全性的最后一道防线。

    🔒

    HTTPS 传输加密

    浏览器和服务器之间的所有通信都通过 HTTPS 加密，即使在公共 Wi-Fi 下，中间人也无法窥探你的账号密码或个人数据。

    🎯
    一句话总结
    浏览器负责展示界面并收集用户操作 → 通过网络发送 HTTP 请求 → 服务器验证身份、执行业务逻辑 → 向 数据库读写数据 → 将结果返回给浏览器渲染。整个过程在毫秒级完成，用户 ID 贯穿始终确保数据隔离。
